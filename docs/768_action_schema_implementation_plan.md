# 768-Entry Action Schema Implementation Plan

## Objective

Replace the current 620-entry, partially contextual action layout with a stable, versioned **768-entry action schema** before meaningful reinforcement-learning training begins.

The finished system must have:

- exactly 768 action indices, `0–767`;
- one complete documented action-family meaning per active index;
- unused indices permanently masked;
- no unrelated meanings sharing one index;
- one centralized action registry;
- structured engine actions separated from neural-network indices;
- schema versioning for replays, saves, histories, and checkpoints;
- exhaustive mask, codec, and dispatch validation;
- deterministic full-game validation before training starts.

Training must not begin until the final pre-training audit passes.

---

# High-Level Architecture

The action system should be separated into three layers.

## 1. Structured game actions

The rules engine should work with meaningful action objects rather than raw integers.

Examples:

```python
PlaceFromPersonalSupply(post_id="route-7-post-2", shape=PieceShape.MERCHANT)

ClaimRouteOffice(route_id="route-7", city_id="lubeck")

PlaceOptionalDisplacementPiece(
    shape=PieceShape.TRADER,
    destination_post_id="route-12-post-1",
)

FinishDisplacement()
```

The engine is responsible for determining which structured actions are legal.

## 2. Action codec

A single codec converts between structured actions and neural-network indices.

```text
Structured action <-> neural-network index
```

Example interface:

```python
class ActionCodec:
    def encode(self, action: GameAction, context: ActionCodecContext) -> int:
        ...

    def decode(self, index: int, context: ActionCodecContext) -> GameAction:
        ...

    def describe(self, index: int, context: ActionCodecContext) -> str:
        ...
```

The codec owns all index ranges, mappings, labels, and validation.

## 3. Action mask

The AI mask should be generated by:

1. asking the engine for legal structured actions;
2. encoding each legal action;
3. marking those indices as legal.

Conceptually:

```python
mask = [False] * ACTION_SPACE_SIZE

context = action_codec.context_for(game_state)
for action in game_state.get_legal_actions():
    index = action_codec.encode(action, context)
    mask[index] = True
```

The mask should not independently recreate game legality wherever that can be avoided.

```text

```

## Required constants

## Suggested range type

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class ActionRange:
    name: str
    start: int
    capacity: int

    @property
    def stop(self) -> int:
        return self.start + self.capacity
```

## Requirements

- Every enabled index must identify one complete, executable Hansa decision.
- UI selection fragments must not be engine actions.

  - decoding rule;

- `ACTION_SCHEMA_VERSION == 2`.
- Every range is centrally defined.
- No overlap exists.
- Identical state revisions and indices decode to identical complete actions.
- All reserved indices are documented.
- The schema document and code agree exactly.
- No engine behavior changes yet.
- Existing tests still pass.

# Milestone 5 — Replace the AI Mask and Dispatcher

## Goal

Switch the AI-facing action path to the new 768-entry schema.

## Required mask behavior

```python
legal_actions = state.get_legal_actions()
mask = action_codec.create_mask(legal_actions)
```

## Required execution behavior

```python
action = action_codec.decode(index, state)
state.apply_action(action)
```

## Requirements

- Mask length must always equal 768.
- Every legal structured action must map to exactly one enabled index.
- Every enabled index must decode successfully.
- Every decoded enabled action must execute successfully.
- Every reserved index must remain disabled.
- No old `620` action-space assumptions may remain in active AI code.
- Index `619` must no longer have unrelated meanings.
- Human and AI paths should converge on the same engine action application path wherever practical.
- Debug labels should come from the codec rather than scattered lookup logic.

## Acceptance criteria

- `len(mask) == 768` in every game state.
- Every `True` mask entry decodes into a legal action.
- Every legal action encodes to a `True` mask entry.
- No reserved index is ever enabled.
- No enabled index is out of range.
- No old mask length remains in active production code.
- Deterministic full games complete successfully.
- Existing supported gameplay remains behaviorally equivalent.

# Milestone 6 — Add Exhaustive Action-Schema Validation

## Goal

Prove that legality, masking, encoding, decoding, and execution agree.

## Core invariant

For every reachable state:

```text
engine legal actions
==
decoded enabled mask actions
```

## Required validation for every enabled index

For each enabled action:

1. decode the index;
2. confirm the action is legal;
3. apply it to a cloned state;
4. confirm no exception occurs;
5. confirm state invariants hold;
6. confirm the resulting state is deterministic.

## Required validation for every engine-legal action

For each legal action:

1. encode it;
2. verify the encoded index is enabled;
3. decode it;
4. verify the round trip preserves meaning;
5. verify no second legal action maps to the same index.

## Required test coverage

- all normal-action phases;
- all route outcomes;
- all city and office choices;
- all income choices;
- all bonus-marker choices;
- all tile and payment choices;
- all upgrades and abilities;
- every displacement branch;
- optional same-shape displacement pieces;
- general-stock and personal-stock sources;
- board fallback choices;
- finish and decline decisions;
- pass/end-turn decisions;
- terminal states;
- nonterminal states;
- save/load restored states;
- replay-restored states.

## Acceptance criteria

- Mask length is always 768.
- Reserved entries are always false.
- Every enabled action executes.
- Every legal action is exposed.
- No illegal action is exposed.
- No duplicate structured actions are returned.
- No duplicate indices are generated.
- Nonterminal states always expose at least one legal action.
- Terminal states expose no gameplay action except explicitly documented terminal controls.
- Seeded complete games finish without invalid-action failures.
- Failures report the seed, turn, phase, state summary, index, and action description.

# Final Design Principles

1. The engine owns legality.
2. Structured actions represent player decisions.
3. The codec owns index assignment.
4. The mask is derived from legal structured actions.
5. Every active index has one stable meaning.
6. Reserved capacity prevents unnecessary output-size changes.
7. Schema versioning prevents silent incompatibility.
8. Tests prove that legality, masking, decoding, and execution agree.
9. Training begins only after the final audit passes.

# Standard Implementation Workflow

For every milestone:

1. Implement only the current milestone.
2. Run Python parsing, Ruff, the required validation, and the full test suite.
3. Perform an independent read-only review.
4. Classify every review finding as:
   - Blocking
   - Major
   - Minor
   - Optional
5. If any Blocking or Major findings exist:
   - fix them;
   - rerun validation;
   - perform another independent review.
6. Repeat the fix, validation, and review cycle until:
   - Blocking = 0;
   - Major = 0;
   - Minor = 0, preferably; otherwise explain why each remaining Minor
     finding is not being resolved.
7. When the milestone is complete:
   - stage only the milestone files;
   - create a commit;
   - report the commit SHA;
   - report the validation results;
   - report the final review summary.
8. Stop and wait for user approval before beginning the next milestone.
